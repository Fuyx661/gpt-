# R3 综合验证与问题修复：进入 DSO 研究前的验收门槛

2026-11-28 作者决定：R3 暂不结束。先处理报告所列五项问题，再将研究重心转向 DSO。保留 R1/R2 模型和历史实验；不新增研究阶段，不把已有样本验证视为真实数据校准或网络安全保证。

依据：R3_RESOURCE_VALIDATION_REPORT.md、TSG_Rolling_M_Cert_Unified_Framework.md v0.2。

## 工作顺序与验收
1. 参数真实性：建立参数级来源登记，区分文献直接值、推导值、实测统计与研究假设。尽可能用 ACN 充电会话和适用负荷数据校准外生分布；明确不能从公开数据获得的私有成本及门槛，采用有依据的合成范围和敏感性分析，不冒称实测。保留同种子配对。
2. 无功模型：CL/EV 按各自基线功率因数同比例减小 P、Q；BESS 只提供额外有功，基线充电无功口径明确。零基线、防止重复扣减、符号、单位、需求计算与 AC 审核一致，均需测试。
3. 反馈：当前已认证可履约合同仅返回 ACCEPT/REJECT；私有成本、门槛和拒绝原因不外泄。技术错误与有效经济拒绝区分，不能把未决或物理不可行误当价格证据；测试状态冻结、单调性、矛盾反馈、跨期失效。
4. 询价：沿统一框架 v0.2，首次 0.20，拒绝后 +0.05，接受锁价、无需二次确认，每 Provider 每期最多一份授标；各期重新初始化。主实验不预设询价次数预算；首次达到 U 有限、Lnet>0 且 (U-Lnet)/Lnet<=10% 停止，零支付特例单列；有效行动穷尽或计算限制时如实标记未达标。明确网格下界是否等于首次报价及最高报价，统一 Oracle 与在线域；不得用 Oracle 误差在线停止。
5. 网络安全：以 R3 的 480 期失败记录为基线，逐项区别公开容量不足、线性 FNA 未找到解、合同离散域不可行、搜索未发现可行解、预测与实际偏差。对代表性失败做离线完整信息参考和 AC 核验；非收敛或局部失败不是全域不可行证明。修复可归因缺陷，保留真实不可行和未决样本，不以人为调参清零失败。报告预测场景与实际场景结果、无需采购与采购成功分开统计。

## 最终验收
五项均有明确实施、证据及剩余边界说明；真实运行资源回归、信息隔离、价格网格及证书、网络映射和完整闭环测试。不能要求所有随机场景天然可行；不能证明的结论不得写成 PASS。现阶段仅冻结修复路线，尚未修改 Flexibility 代码；具体校准与网格边界待落实。通过后再开展 DSO 方法优越性研究。
