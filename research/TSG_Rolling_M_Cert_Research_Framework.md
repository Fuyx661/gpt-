# TSG 研究方案：Rolling M-Cert 滚动有限反馈采购框架

> 版本：2026-11-24；停止规则同步修订：2026-11-28  
> 研究方向：面向异质自主柔性资源的滚动有限反馈采购与经济质量认证  
> 算法暂定名称：Rolling M-Cert

---

**修订说明：** 主算法与主实验不预设询价次数上限，首次达到 10% 有效经济质量证书即停止；询价次数为性能指标。以 [统一研究框架](TSG_Rolling_M_Cert_Unified_Framework.md) 最新版及 [修改意见](修改意见.md) 为准，其他历史设定保留。

## 一、研究背景：我们要解决什么问题？

### 1.1 实际应用背景

随着分布式能源、电池储能、电动汽车和可控负荷大量接入配电网，配电系统运营商（DSO）需要根据未来负荷和分布式电源预测，提前识别可能出现的电压越限等问题，并通过采购柔性资源改善配电网运行。

本文考虑三类异质柔性资源：

- **BESS：电池储能系统。** 通过调整充放电功率提供柔性，受到 SOC、充放电功率和剩余能量约束。
- **CL：可控负荷。** 通过调整生产或用电计划提供柔性，受到生产约束、累计削减预算和生产损失约束。
- **EV Aggregator：电动汽车聚合商。** 通过调整车辆充电功率提供柔性，受到车辆接入时间、剩余电量和离站需求约束。

三类资源都能提供柔性，但它们的物理运行特性、经济成本和参与意愿存在明显差异。

### 1.2 当前采购面临的三个困难

**困难一：资源异质性。**

三类资源的物理能力不同，不能简单地把它们看成相同的柔性供应商。

**困难二：自主参与与信息不对称。**

每个 Provider 都有自己的履约成本和最低参与收益要求。DSO 不知道其真实成本，也不知道其最低接受价格，而且接受门槛可能随资源状态变化。

**困难三：有限反馈与网络约束。**

DSO 向 Provider 提出合同和报价，每次只获得 ACCEPT 或 REJECT。主算法不人为规定总询价次数，但应尽可能高效地达到经济目标；有限合同和报价网格使有效询价行动自然有限。

即使找到愿意接受报价的 Provider，采购组合也不一定满足配电网 AC 运行约束。

因此，DSO 面临的问题是：

> 在不知道 Provider 真实成本和接受门槛、只能获得有限二元反馈的情况下，如何找到满足柔性需求和 AC 网络约束的低支付采购组合？

### 1.3 最终研究问题

建议将研究问题正式确定为：

> 在三类异质资源具有不同物理状态、私有成本和状态相关接受门槛的情况下，DSO 仅通过有限 ACCEPT/REJECT 反馈，如何联合利用支付上下界、合同组合结构和 AC 网络可行性，主动选择下一次最有价值的询价，并实现具有可验证经济质量保证的滚动柔性采购？

这里有三个子问题：

1. 如何统一描述三类异质资源的物理运行特性和自主参与行为？
2. 如何利用有限二元反馈构造支付上下界，并通过上下界指导下一次询价？
3. 如何将 AC 网络可行性纳入采购决策，并在资源状态变化后继续保持经济质量评价的有效性？

## 二、合同机制：我们究竟如何采购？

采用**滚动单时段正式合同机制**。

每个时段只对当前采购任务形成正式合同，未来时段仅进行预测和状态评估。

合同定义：

\[
\mathcal C_{ij,t}=(t,q_{ij,t},E_{ij,t},\lambda_{ij,t})
\]

其中：

| 符号 | 含义 |
|---|---|
| \(i\) | Provider |
| \(j\) | 候选合同编号 |
| \(t\) | 当前履约时段 |
| \(q_{ij,t}\) | 合同要求提供的柔性功率 |
| \(E_{ij,t}\) | 合同计费能量 |
| \(\lambda_{ij,t}\) | DSO 提出的单位激励价格 |

\[
E_{ij,t}=q_{ij,t}\Delta t
\]

合同支付：

\[
P_{ij,t}=\lambda_{ij,t}E_{ij,t}
\]

例如：

- 第 1 时段，BESS 接受 4 kW 放电合同。
- 合同执行后，BESS 的 SOC 下降。
- 第 2 时段，DSO 根据新的 SOC 重新判断其可用能力和接受价格。
- DSO 再决定是否向该 Provider 采购。

**滚动采购过程：**

| 时段 | 采购行为 | 后续处理 |
|---|---|---|
| 时段 1 | 正式采购 | 合同执行、状态更新 |
| 时段 2 | 基于最新状态重新采购 | 合同执行、状态更新 |
| 时段 3 | 再次滚动采购 | 继续更新状态 |

这里需要明确：当前合同执行会改变未来状态，但当前研究的经济质量证书是逐时段建立的，不直接宣称整个滚动周期达到了动态全局最优。

## 三、数学建模

数学模型分为六个部分：

1. 三类异质资源物理模型。
2. Provider 自主参与模型。
3. 有限二元反馈模型。
4. 滚动状态更新模型。
5. DSO 采购优化模型。
6. 支付上下界与双重经济收敛模型。

### 3.1 三类异质资源物理模型

定义：

\[
\mathcal I=\mathcal I_{BESS}\cup\mathcal I_{CL}\cup\mathcal I_{EV}
\]

统一采购接口：

\[
\boxed{q_{ij,t}\in\mathcal Q_i(s_{i,t})}
\]

其中 \(s_{i,t}\) 为资源状态，\(\mathcal Q_i\) 为当前状态下的物理可行域。

#### （1）BESS

定义：

- \(SOC_{i,t}\)：当前电池荷电状态。
- \(E_i^{bat}\)：电池额定能量。
- \(\eta_i^{dis}\)：放电效率。
- \(P_i^{dis,max}\)：最大放电功率。

采用合同额外放电的简化模型：

\[
0\leq q_{i,t}^{BESS}\leq P_i^{dis,max}
\]

\[
SOC_{i,t+1}=SOC_{i,t}
-\frac{q_{i,t}^{BESS}\Delta t}{\eta_i^{dis}E_i^{bat}}
\]

\[
SOC_i^{min}\leq SOC_{i,t+1}\leq SOC_i^{max}
\]

#### （2）CL

定义：

- \(b_{i,t}\)：当前基线负荷。
- \(P_i^{min}\)：最低允许生产负荷。
- \(\gamma_i\)：最大削减比例。
- \(B_{i,t}\)：剩余削减能量预算。

当前削减功率：

\[
0\leq q_{i,t}^{CL}\leq
\min\{\gamma_i b_{i,t},\ b_{i,t}-P_i^{min},\ \bar q_i^{svc}\}
\]

剩余削减预算：

\[
B_{i,t+1}=B_{i,t}-q_{i,t}^{CL}\Delta t
\]

\[
B_{i,t+1}\geq0
\]

当前简化模型暂不考虑削减后的生产反弹，若实际 CL 存在负荷恢复过程，需要增加跨时段约束。

#### （3）EV Aggregator

定义：

- \(e_{v,t}\)：车辆当前剩余电量。
- \(p_{v,t}^{0}\)：正常充电基线功率。
- \(p_{v,t}^{EV}\)：实际充电功率。
- \(a_{v,t}\)：车辆是否接入。
- \(t_v^{dep}\)：离站时刻。
- \(e_v^{req}\)：离站最低电量。

EV 通过降低正常充电功率提供柔性：

\[
q_{v,t}^{EV}=p_{v,t}^{0}-p_{v,t}^{EV}
\]

\[
0\leq p_{v,t}^{EV}\leq a_{v,t}P_v^{max}
\]

\[
q_{i,t}^{EV}=\sum_{v\in\mathcal V_i}q_{v,t}^{EV}
\]

车辆电量更新：

\[
e_{v,t+1}=e_{v,t}+\eta_vp_{v,t}^{EV}\Delta t
\]

离站要求：

\[
e_{v,t_v^{dep}}\geq e_v^{req}
\]

还需要保证当前减少充电之后，剩余连接时间内仍有满足离站要求的充电计划。

**统一模型的意义：**

三类资源内部使用不同的物理约束，但最终都通过 \(q_{ij,t}\) 进入 DSO 的采购优化模型。

需要特别注意，DSO 只能使用已公开、申报或经过验证的资源能力信息，不能在在线算法中直接读取 Provider 未公开的内部状态。

### 3.2 Provider 自主参与模型

定义：

- \(C_i(q_{ij,t};s_{i,t})\)：Provider 履行合同的私有增量成本。
- \(\kappa_i(s_{i,t})\)：Provider 的最低参与收益要求。

三类资源的成本来源：

\[
C_i=
\begin{cases}
C_i^{deg}+C_i^{opp},& BESS\\
C_i^{prod}+C_i^{discomfort},& CL\\
C_i^{charge}+C_i^{user},& EV
\end{cases}
\]

Provider 接受条件：

\[
\boxed{
\lambda_{ij,t}E_{ij,t}
-C_i(q_{ij,t};s_{i,t})
\geq\kappa_i(s_{i,t})
}
\]

因此，有效接受价格阈值：

\[
\boxed{
\tau_{ij,t}^{eff}
=
\frac{C_i(q_{ij,t};s_{i,t})+\kappa_i(s_{i,t})}
{E_{ij,t}}
}
\]

接受规则：

\[
\lambda_{ij,t}\geq\tau_{ij,t}^{eff}
\]

这里的 \(\tau_{ij,t}^{eff}\) 是私有信息，DSO 不直接知道其真实值。

三类成本函数需要后续进行文献溯源和参数校准，不能仅凭统一的数学形式就认定已经充分体现资源异质性。

### 3.3 原始二元反馈模型

定义：

\[
a_{ij,t}^{(r)}\in\{0,1\}
\]

其中：

\[
a_{ij,t}^{(r)}=
\begin{cases}
1,& ACCEPT\\
0,& REJECT
\end{cases}
\]

在合同物理可履约、合同条件固定、资源状态固定、接受规则对价格单调且反馈确定的前提下：

\[
ACCEPT\Rightarrow\tau_{ij,t}^{eff}\leq\lambda_{ij,t}^{(r)}
\]

\[
REJECT\Rightarrow\tau_{ij,t}^{eff}>\lambda_{ij,t}^{(r)}
\]

因此可以更新：

\[
\boxed{
\underline\tau_{ij,t}^{(r)}
<
\tau_{ij,t}^{eff}
\leq
\overline\tau_{ij,t}^{(r)}
}
\]

其中：

\[
\underline\tau_{ij,t}^{(r)}
=
\max\{\underline\tau_{ij,t}^{(0)},\text{历史有效拒绝报价}\}
\]

\[
\overline\tau_{ij,t}^{(r)}
=
\min\{\overline\tau_{ij,t}^{(0)},\text{历史有效接受报价}\}
\]

重要的是：

**如果合同在当前状态下物理上无法履行，REJECT 不能被直接解释为报价不足。**

因此，进入严格价格区间学习的询价合同必须先满足物理可履约条件。状态变化后，必须重新建立有效价格区间。

### 3.4 滚动状态更新模型

统一表示为：

\[
\boxed{
s_{i,t+1}=f_i(s_{i,t},q_{i,t}^{exec},w_{i,t})
}
\]

其中：

- \(q_{i,t}^{exec}\)：实际执行的柔性。
- \(w_{i,t}\)：外部运行变化。

三类资源状态更新：

| 资源 | 当前执行 | 下一时段状态 |
|---|---|---|
| BESS | 放电 | SOC 下降 |
| CL | 削减负荷 | 剩余削减预算减少 |
| EV | 调整充电 | 电量及可用状态变化 |

没有获得授标的 Provider 也应按照其正常基线运行更新状态，不能简单认为状态保持不变。

每个新时段重新建立接受价格区间和支付上下界。

### 3.5 DSO 采购优化模型

#### （1）目标函数

DSO 的当前时段采购目标：

\[
\boxed{
\min P_t=
\sum_{i\in\mathcal I}
\sum_{j\in\mathcal J_{i,t}}
\sum_r
E_{ij,t}\lambda_{ij,t}^{(r)}y_{ij,t}^{(r)}
}
\]

目标是在满足柔性需求、Provider 参与约束和 AC 网络约束的条件下，最小化当前实际采购支付。

整个运行周期累计支付：

\[
\boxed{J_T=\sum_{t=1}^{T}P_t}
\]

注意：当前模型是逐时段滚动采购，累计支付是全周期评价指标，并不意味着当前算法已经解决全周期动态最优控制问题。

#### （2）决策变量

| 决策变量 | 类型 | 含义 |
|---|---|---|
| \(u_{ij,t}^{(r)}\) | 0-1 | 是否询问合同 |
| \(\lambda_{ij,t}^{(r)}\) | 连续或离散 | 当前询价报价 |
| \(y_{ij,t}^{(r)}\) | 0-1 | 是否将已接受报价纳入最终授标 |
| \(V_{n,t}\) | 连续 | 节点电压幅值 |
| \(\theta_{n,t}\) | 连续 | 节点电压相角 |

其他量：

- \(q_{ij,t}\)：候选合同固定属性。
- \(a_{ij,t}^{(r)}\)：Provider 的反馈。
- \(s_{i,t}\)：当前资源状态。

它们不是 DSO 的同类决策变量。

#### （3）约束条件

**约束一：满足柔性需求**

\[
\boxed{
\sum_{i,j,r}q_{ij,t}y_{ij,t}^{(r)}
\geq F_t^{req}
}
\]

**约束二：同一 Provider 同一时段最多授标一份合同**

\[
\boxed{
\sum_{j,r}y_{ij,t}^{(r)}\leq1
}
\]

**约束三：只能授标已接受的合同**

\[
y_{ij,t}^{(r)}\leq a_{ij,t}^{(r)}
\]

\[
y_{ij,t}^{(r)}\leq u_{ij,t}^{(r)}
\]

**询价次数（效率指标，不是预设预算）**

\[
N_t=\sum_{i,j,r}u_{ij,t}^{(r)}.
\]

主算法不设总询价次数上限。有限合同域及固定报价网格下，禁止重复报价，合同接受或最高报价拒绝后结束该合同的查询。若候选合同数为 \(M_t\)，网格档数为 \(K\)，则 \(N_t\le M_t K\) 是协议自然产生的穷尽上界。

每轮最多询问一份合同：

\[
\sum_{i,j}u_{ij,t}^{(r)}\leq1
\]

**约束五：资源物理可行性**

\[
q_{ij,t}\in\mathcal Q_i(s_{i,t})
\]

**约束六：AC 网络运行约束**

当前节点有功负荷：

\[
P_{n,t}^{L}
=
P_{n,t}^{0}
-
\sum_{i:b_i=n}\sum_{j,r}
q_{ij,t}y_{ij,t}^{(r)}
\]

这里假设柔性响应单位功率因数，无功负荷保持基线：

\[
Q_{n,t}^{L}=Q_{n,t}^{0}
\]

AC 潮流：

\[
P_{n,t}^{inj}
=
V_{n,t}\sum_mV_{m,t}
[
G_{nm}\cos\theta_{nm,t}
+
B_{nm}\sin\theta_{nm,t}
]
\]

\[
Q_{n,t}^{inj}
=
V_{n,t}\sum_mV_{m,t}
[
G_{nm}\sin\theta_{nm,t}
-
B_{nm}\cos\theta_{nm,t}
]
\]

电压约束：

\[
\boxed{0.95\leq V_{n,t}\leq1.05}
\]

当前只考虑 IEEE 33-bus 节点电压约束，不额外声称已经考虑线路热容量约束。

这里的采购模型是最终授标优化的表达；实际询价过程是一个根据反馈历史逐步选择行动的序贯决策过程，不能将其误认为一次性静态优化。

## 四、支付上下界：如何判断采购经济质量？

这是整篇论文的核心理论部分之一。

DSO 不知道 Provider 的真实接受价格，因此无法直接计算完整信息下的最优采购支付。

我们需要构造两个界限。

### 4.1 支付下界 \(L_{t,r}\)

定义：

\[
\boxed{
L_{t,r}
=
\min_{x\in\mathcal F_{t,r}^{rel}}
\sum_{i,j}E_{ij,t}
\underline\tau_{ij,t}^{(r)}x_{ij}
}
\]

其中：

- \(\underline\tau_{ij,t}^{(r)}\)：根据有效二元反馈得到的接受价格下界。
- \(\mathcal F_{t,r}^{rel}\)：当前采购问题的乐观松弛可行域。
- \(x_{ij}\)：是否选择对应合同。

这里有两个关键条件：

1. 价格下界必须来自有效反馈，不能把物理不可履约导致的拒绝当成价格证据。
2. 松弛可行域必须包含真实 AC 可行采购集合：

\[
\mathcal F_{t,r}^{AC}\subseteq\mathcal F_{t,r}^{rel}
\]

例如，暂时忽略 AC 网络约束可以构造一个较松的支付下界。如果要利用网络信息收紧下界，就必须证明所采用的网络松弛或组合排除规则有效。

### 4.2 可行支付上界 \(U_{t,r}\)

定义：

\[
\boxed{
U_{t,r}
=
\min_{x\in\mathcal F_{t,r}^{AC}}
\sum_{i,j}E_{ij,t}\lambda_{ij,t}^{acc}x_{ij}
}
\]

其中：

- 只能使用已经接受的合同。
- 必须满足 Provider 授标约束。
- 必须满足当前柔性需求。
- 必须通过 AC 网络验证。

如果尚未找到可行采购组合：

\[
U_{t,r}=+\infty
\]

### 4.3 Oracle 最优支付

定义：

\[
P_t^\star
\]

表示在完整信息下，同一资源状态、同一候选合同集合、同一报价网格和同一 AC 可行性定义内的最优采购支付。

Oracle 可以获得 Provider 的真实接受门槛，但只能用于离线实验，不允许参与在线询价和停止决策。

因此，在所有界有效的前提下：

\[
\boxed{L_{t,r}\leq P_t^\star\leq U_{t,r}}
\]

这就是我们后续建立经济质量证书的基础。

## 五、收敛机制：双重经济收敛方案

**已确定：方案 B。**

这一部分是本次研究方案中最重要的设计之一。

我们不再简单地将：

\[
\frac{U-L}{L}\leq10\%
\]

作为唯一的收敛标准。

因为这只能说明上下界足够接近，不能完整反映实际采购支付的表现。

我们需要区分三个采购里程碑。

### 5.1 第一阶段：可行性收敛

定义：

\[
\boxed{U_{t,r}<+\infty}
\]

含义：已经找到至少一个满足柔性需求、Provider 授标约束和 AC 网络约束的采购组合。

例如，DSO 询价了 8 次，终于找到：

- BESS 提供 3 kW；
- CL 提供 2 kW；
- EV 提供 4 kW。

总柔性满足需求，并且通过 AC 潮流验证。

此时采购成功，但不代表支付已经足够低。

### 5.2 第二阶段：实际经济收敛

定义实际经济误差：

\[
\boxed{
g_{t,r}^{Oracle}
=
\frac{U_{t,r}-P_t^\star}{P_t^\star}
}
\]

其中：

- \(U_{t,r}\)：截至第 \(r\) 次询价，已经找到的最佳 AC 可行采购支付。
- \(P_t^\star\)：完整信息下的 Oracle 最优支付。

当：

\[
\boxed{g_{t,r}^{Oracle}\leq0.10}
\]

认为实际经济达标。

这回答：

**DSO 实际买到的柔性是否足够便宜？**

但 Oracle 只用于离线评价，DSO 在线并不知道这个误差。

### 5.3 第三阶段：可验证经济收敛

定义证书经济误差：

\[
\boxed{
g_{t,r}^{Cert}
=
\frac{U_{t,r}-L_{t,r}}{L_{t,r}}
}
\]

其中：

- \(U_{t,r}\)：当前可行支付上界。
- \(L_{t,r}\)：当前有效支付下界。

当：

\[
\boxed{g_{t,r}^{Cert}\leq0.10}
\]

认为获得了 10% 经济质量证书。

这回答：

**DSO 是否已经掌握足够的信息，能够证明当前采购方案的经济质量？**

### 5.4 两种经济收敛之间的数学关系

由于：

\[
L_{t,r}\leq P_t^\star\leq U_{t,r}
\]

所以：

\[
\begin{aligned}
g_{t,r}^{Oracle}
&=\frac{U_{t,r}}{P_t^\star}-1\\
&\leq\frac{U_{t,r}}{L_{t,r}}-1\\
&=g_{t,r}^{Cert}
\end{aligned}
\]

因此：

\[
\boxed{g_{t,r}^{Oracle}\leq g_{t,r}^{Cert}}
\]

如果：

\[
g_{t,r}^{Cert}\leq10\%
\]

就必然有：

\[
U_{t,r}\leq1.10L_{t,r}\leq1.10P_t^\star
\]

这说明：

**可验证经济收敛必然保证实际经济收敛，但实际经济收敛不一定意味着已经获得证书。**

这也是采用双重经济收敛的数学理由。

### 5.5 为什么需要经济认证延迟？

增加一个指标：

**Economic Certification Delay（经济认证延迟）。**

定义首次实际经济达标询价次数：

\[
N_{t,\varepsilon}^{Oracle}
=
\min\left\{
r:g_{t,r}^{Oracle}\leq\varepsilon
\right\}
\]

定义首次证书经济达标询价次数：

\[
N_{t,\varepsilon}^{Cert}
=
\min\left\{
r:g_{t,r}^{Cert}\leq\varepsilon
\right\}
\]

其中：

\[
\varepsilon=0.10
\]

经济认证延迟：

\[
\boxed{
D_{t,\varepsilon}
=
N_{t,\varepsilon}^{Cert}
-
N_{t,\varepsilon}^{Oracle}
}
\]

举个例子：

假设 Oracle 最优支付为 100：

| 询价次数 | 当前采购支付 | 实际经济误差 | 证书经济误差 |
|---|---:|---:|---:|
| 8 | 130 | 30% | 60% |
| 12 | 108 | 8% | 35% |
| 15 | 105 | 5% | 20% |
| 18 | 104 | 4% | 9% |

那么：

- 第 12 次询价：实际经济达标。
- 第 18 次询价：证书经济达标。

因此：

\[
D_{t,\varepsilon}=18-12=6
\]

这意味着 DSO 找到足够便宜的方案之后，还需要 6 次询价才能获得经济质量证明。

这能够体现上下界机制的真正价值。

**双重经济收敛的关系：**

1. 找到可行采购方案：已经能够满足需求和网络约束。
2. 实际经济达标：通过 Oracle 判断采购支付已经达到 10% 目标。
3. 可验证经济达标：通过支付上下界证明采购支付达到 10% 经济质量要求。

经济认证延迟衡量第二阶段到第三阶段之间的额外询价成本。

### 5.6 特殊情况处理

不能忽略以下情况：

| 情况 | 处理方式 |
|---|---|
| \(U=+\infty\) | 尚无可行采购方案，不计算经济误差 |
| \(L=0,U>0\) | 相对证书误差无定义，不宣称达到 10% |
| \(L=U=0\) | 单独记录零支付最优 |
| \(L>U\) | 证书异常，停止认证并排查 |
| Oracle 未认证最优性 | 只能报告 best-known benchmark，不能称为精确 Oracle 误差 |

如果终止时实际经济已经达标，但证书没有达标，需要记录为认证延迟未完整观测，不能把实际终止次数当作已经达标的询价次数。

## 六、证书驱动主动询价算法

这一部分决定了上下界是否真正进入 DSO 的决策过程。

我们希望做到：

**上下界不仅用于评价采购结果，还要直接决定 DSO 下一次应该询问谁、询问哪份合同、给出什么价格。**

### 6.1 询价行动

定义：

\[
a=(i,j,\lambda)
\]

表示：

- 询问 Provider \(i\)；
- 询问合同 \(j\)；
- 提出报价 \(\lambda\)。

反馈只有：

\[
z\in\{ACCEPT,REJECT\}
\]

### 6.2 两种反馈的反事实更新

对每个候选询价行动，分别模拟：

- 如果 Provider 接受，会怎样更新支付上下界？
- 如果 Provider 拒绝，会怎样更新支付上下界？

得到：

\[
GAP_{t,r+1}^{ACCEPT}(a)
\]

\[
GAP_{t,r+1}^{REJECT}(a)
\]

### 6.3 下一次询价选择

在已经获得有限可行上界、能够有效计算证书的情况下，采用最坏情况证书改善原则：

\[
\boxed{
a_{t,r}^{*}
=
\arg\min_{a\in\mathcal A_{t,r}}
\max_{z\in\{ACCEPT,REJECT\}}
GAP_{t,r+1}^{z}(a)
}
\]

通俗解释：

DSO 不再随意选择下一个 Provider，而是优先询问那些即使在最坏反馈情况下，也最有可能改善经济质量证书的合同。

候选行动集合需要考虑：

1. 当前支付下界。
2. 合同组合结构。
3. 同一 Provider 单合同限制。
4. AC 网络可行性信息。
5. 当前状态下有效的接受价格区间。

这里需要区分两个阶段：

- **尚未找到可行方案时：** 以发现可行采购组合为首要目标，此时 \(U=+\infty\)，不能使用有限 GAP 进行排序。
- **已经找到可行方案后：** 进入证书驱动询价阶段，利用最坏情况证书 GAP 选择下一次询价。

当前主方案保留最坏情况证书 GAP 驱动机制，不在这次修改中擅自改为其他目标经济残差驱动策略。

## 七、完整算法：Rolling M-Cert

建议暂时将算法命名为：

**Rolling M-Cert：滚动状态感知的证书驱动主动采购算法。**

完整流程如下：

1. **更新当前运行信息：** 获取最新负荷、DG 预测和三类资源的可用状态。
2. **生成当前时段合同：** 生成 BESS、CL、EV 的候选柔性合同。
3. **初始化接受价格区间：** 使用当前状态下有效的信息初始化价格上下界。
4. **主动选择下一次询价：** 综合支付下界、合同组合结构和网络信息，选择最有价值的询价行动。
5. **接收二元反馈：** Provider 返回 ACCEPT 或 REJECT，更新有效价格区间。
6. **更新支付上下界：** 计算当前有效的 \(L_{t,r}\) 和 \(U_{t,r}\)。
7. **经济质量评价与停止：** 记录可行性发现、实际经济收敛（离线）和证书经济收敛。首次满足 \(U<+\infty,\ L>0,\ (U-L)/L\leq0.10\) 时停止询价；严格认证的零支付最优单独处理。否则继续有效询价，直至行动耗尽并完成必要验证、策略无法继续或计算中断。未达标则记录实际终止原因，不视为收敛。Oracle 不参与在线停止。
8. **确定最终采购组合：** 从已接受且已通过 AC 验证的合同组合中选择最低支付方案；若无已验证可行方案则不授标。记录 NO_FEASIBLE_FOUND、FEASIBLE_UNCERTIFIED 或 CERTIFIED 及终止原因。
9. **执行合同并更新资源状态：** 更新 BESS SOC、CL 剩余削减预算和 EV 剩余电量。
10. **进入下一时段：** 重新初始化状态相关接受价格区间和支付证书。

## 八、实验设计

实验必须与三个贡献和双重经济收敛机制对应。

建议保留 E0、E1、E2、E3 四个部分。

### E0：模型可靠性验证

**目的：** 验证数学模型是否正确。

主要内容：

- BESS、CL、EV 物理约束是否成立。
- 资源状态更新是否正确。
- 二元反馈能否正确更新接受价格区间。
- 支付下界是否始终不超过 Oracle 最优支付。
- 支付上界是否来自真实接受且 AC 可行的采购组合。
- 经济质量证书是否正确。

特别需要测试：

\[
L_{t,r}\leq P_t^\star\leq U_{t,r}
\]

在所有有效测试实例中是否成立。

### E1：自适应询价算法对比

**目的：** 验证 M-Cert 是否比现有方法更有效地找到低支付采购组合。

比较对象：

- B0–B3。
- 原始 M。
- M-Cert。
- Oracle（完整信息离线参考）。

核心指标：

| 指标 | 目的 |
|---|---|
| 采购成功率 | 能否找到可行组合 |
| 终止时最终支付 | 谁买得更便宜 |
| 实际 Oracle 误差 | 实际经济质量 |
| 询价次数 | 信息获取效率 |
| AC 审核次数 | 网络验证开销 |
| 运行时间 | 算法计算成本 |

Oracle 不是在线竞争算法，而是完整信息下的离线最优参考。

### E2：双重经济收敛实验

**核心实验。**

**目的：** 不预设询价次数上限，验证算法能否以更低支付和更少询价达到统一经济质量目标。

比较对象：

- B3。
- 原始 M。
- M-Cert。
- Oracle 作为离线最优参考。

核心指标：

| 指标 | 具体含义 |
|---|---|
| \(P_{final}\) | 终止时最佳已验证采购支付 |
| \(P_{\varepsilon}^{Oracle}\) | 首次实际经济达标时的采购支付 |
| \(P_{\varepsilon}^{Cert}\) | 首次证书经济达标时的采购支付 |
| \(N_{\varepsilon}^{Oracle}\) | 首次实际经济达标的询价次数 |
| \(N_{\varepsilon}^{Cert}\) | 首次证书经济达标的询价次数 |
| \(R_{\varepsilon}^{Oracle}\) | 终止前实际经济达标率 |
| \(R_{\varepsilon}^{Cert}\) | 终止前证书经济达标率 |
| \(D_{\varepsilon}\) | 经济认证延迟 |
| \(g_{final}^{Cert}\) | 终止时的证书误差 |

建议重点展示三类结果：

1. 不同方法的实际经济误差和证书经济误差随询价次数的变化。
2. 不同方法达到 10% 经济目标所需的询价次数及支付。
3. 不同方法的经济认证延迟和终止前达标率。

特别注意：

不能只统计成功收敛的样本而忽略失败样本。终止仍未达标的样本应保留，并报告未达标比例和终止原因。Oracle 无法认证最优性的实例也不能直接当作精确经济误差样本。

### E3：机制消融实验

**目的：** 验证各机制究竟发挥了什么作用。

建议比较：

- 完整 M-Cert。
- 去掉网络信息的版本。
- 去掉反事实反馈分析的版本。
- 去掉证书驱动机制的版本。

重点观察：

| 研究问题 | 对应指标 |
|---|---|
| 支付下界是否有助于降低采购支付？ | 最终支付、Oracle 误差 |
| 网络信息是否改善经济证书？ | 下界、证书 GAP |
| 反事实分析是否改善询价选择？ | 询价次数、证书改善 |
| 完整机制是否协同有效？ | 实际达标率、证书达标率、认证延迟 |

这里必须区分：如果某个机制只是提高了支付下界 \(L\)，但没有降低实际采购支付 \(U\)，那么只能说它改善了经济认证能力，不能声称它降低了采购成本。

### 动态场景

建议使用三个场景：

| 场景 | 设置 | 主要验证内容 |
|---|---|---|
| S1：常规运行 | 资源充足，预测误差较小 | 基本采购性能 |
| S2：资源状态变化 | BESS 连续放电、CL 削减预算减少、EV 陆续离站 | 滚动状态更新 |
| S3：网络敏感场景 | 预测误差较大，部分节点电压接近边界 | 网络可行性与主动询价 |

所有算法采用相同的初始状态、Provider 私有参数、网络参数、当前相同状态下的候选合同域、报价网格、反馈口径和 10% 经济停止目标，采用一致的外部证书计算与网络验证规则。实际询价次数由各方法决定，不要求相同。固定预算仅作可选补充实验。

## 十、目前模型仍然需要解决的四个关键问题

虽然整体框架已经比较完整，但不建议现在直接冻结所有公式。

还有四个问题需要进一步审查。

### 问题 1：三类资源的经济成本函数

需要分别明确 BESS 退化成本、CL 生产损失、EV 用户不便成本的来源，并避免重复计算。

### 问题 2：二元反馈与物理可行性的关系

必须保证用于学习严格价格区间的合同具有物理可履约性。否则 REJECT 不能直接作为价格下界证据。

### 问题 3：AC 网络如何真正进入支付下界

需要证明网络松弛和组合排除规则有效。AC 潮流不收敛本身不能直接当作不可行证明。

### 问题 4：逐时段收敛与全周期经济性

当前证书只保证当前时段的经济质量。整个周期的累计支付：

\[
J_T=\sum_{t=1}^{T}P_t
\]

需要通过实验评价，不能直接声称它具有全局动态最优性证书。

## 十一、最终研究定位

建议将整篇 TSG 论文概括为：

> 本文研究一种面向 BESS、CL 和 EV 三类异质自主柔性资源的滚动有限反馈采购机制。在 Provider 私有成本和状态相关接受门槛未知、DSO 仅获得有限 ACCEPT/REJECT 反馈的条件下，利用支付上下界建立逐时段可验证的采购经济质量证书，并结合合同组合结构和 AC 网络可行性设计证书驱动的主动询价算法。进一步通过实际经济收敛与可验证经济收敛的双重评价机制，衡量不预设询价预算时的实际采购经济性和经济认证效率，实现连续运行过程中的网络可行低支付柔性采购。

整篇论文的核心逻辑是：

1. **三类异质资源：** 不同物理状态、运行成本和参与门槛。
2. **有限二元反馈：** 学习当前状态下有效的接受价格区间。
3. **支付上下界：** 构造经济质量证书。
4. **证书驱动主动询价：** 结合合同组合结构和 AC 网络信息。
5. **双重经济收敛：** 实际经济达标 + 可验证经济达标。
6. **合同执行与资源状态更新：** 进入下一时段，重新采购。
